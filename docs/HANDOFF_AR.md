# تسليم المشروع والمتابعة من جهاز آخر

## الحالة التي تم التحقق منها

- المستودع العام: <https://github.com/marcel513/valetax-trading-platform>، والفرع الأساسي `main`.
- المشروع أساس **Demo فقط** متعدد المستخدمين: API ولوحة مستخدم وإدارة في `platform_app/api.py`، بوت تليجرام في `platform_app/bot.py`، قاعدة SQLite في `platform_app/db.py`، وإكسبرت MT5 في `ea/ValetaxDemoEA.mq5`.
- `StrategyProvider` موجود في `platform_app/strategy.py`، لكن المزود الحالي يدوي وموسوم `DEMO_ONLY`. لا توجد استراتيجية SES نهائية في المستودع العام، ولا دفع فعلي، ولا تداول بحسابات حقيقية.
- نجحت 10 اختبارات Python. بُني EA الإصدار 1.001 في MetaEditor الخاص بـValetax مع 0 أخطاء و0 تحذيرات.
- في 2026-09-25 رُبط حساب Valetax Demo فعليًا عبر رمز مؤقت، ووصلت نبضات HTTPS ومواصفات `XAUUSD.vx`. نُفذت صفقة Demo واحدة بحجم 0.01 لوت ووقف خسارة، ثم أُغلقت وتأكدت رسائل الفتح والإغلاق ونتائج `/trades` و`/today`. هذه تجربة وظيفة واحدة وليست قياس أداء؛ التفاصيل في [OPERATIONS.md](OPERATIONS.md).
- عند آخر تحقق: لا مراكز مفتوحة، والسماح بصفقات جديدة **معطّل من الخادم**. اختار المستخدم إبقاء `LocalPause=false` داخل EA ليستمر الاتصال؛ لذلك افحص الحالة من جديد قبل أي اختبار.

## ما لا يُنقل عبر GitHub

ملف `.env`، رمز البوت، قاعدة البيانات الفعلية، رمز EA المحلي، رموز الربط، أرقام الحسابات، سجلات المستخدمين، ونفق HTTPS المؤقت مستبعدة عمدًا. نسخ المستودع على جهاز ثانٍ ينقل **الكود والتوثيق والاختبارات فقط**؛ لا ينقل تشغيل البوت أو مستخدميه أو ربط حساب MT5 الحالي. للمشاركة في نفس الحالة الحية بين أجهزة متعددة، انقل الخادم وقاعدة البيانات بصورة آمنة إلى استضافة دائمة، ثم اربط EA بها. لا تشغّل عاملَي polling للبوت نفسه في الوقت نفسه.

## بدء العمل من جهاز ثانٍ

1. ثبّت Git وPython 3.11+، ثم نفّذ:

   ```powershell
   git clone https://github.com/marcel513/valetax-trading-platform.git
   cd valetax-trading-platform
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install -r requirements.txt
   python -m pytest -q
   ```

2. إن أردت تطوير الكود فقط، تكفي الاختبارات ولا حاجة إلى رمز بوت أو MT5. لتشغيل نسخة محلية مستقلة، انسخ `.env.example` إلى `.env` واملأ القيم محليًا، ثم اتبع [README](../README.md). لا تنسخ `.env` إلى GitHub.
3. قبل كل عمل: `git pull --ff-only`. بعد فحص التغييرات والأسرار: `git add` للملفات المقصودة، `git commit`، ثم `git push origin main` وتحقق من ظهور commit على GitHub.
4. المستودع عام ويمكن لأي حساب مشاهدته أو نسخه. لكي يدفع حساب GitHub الثاني إلى **نفس** المستودع، ادعه من حساب المالك عبر **Settings → Collaborators → Add people**، ثم اقبل الدعوة من الحساب الثاني وسجّل دخول Git عليه.

## المتبقي حسب الأولوية

1. **تشغيل مستمر:** استضافة HTTPS ثابتة بدل النفق المؤقت، نقل قاعدة البيانات والأسرار بشكل آمن، نسخ احتياطي واستعادة مجرّبان، خدمة تعيد تشغيل API والبوت، ومراقبة الاتصال والإنذارات. أبقِ عامل Telegram polling واحدًا.
2. **تقوية الأمان قبل مستخدمين فعليين:** مراجعة حماية جلسات الويب ونماذج التعديل، تحديد معدل طلبات الربط والدخول، تدوير الرموز وإلغاؤها، وعزل المستخدمين والصلاحيات في اختبارات أوسع. الخادم يثق حاليًا بتقرير EA الموثّق برمزه، ولا يستطيع وحده إثبات نوع حساب الوسيط أو صحة كل تنفيذ؛ صمّم وسيلة تحقق أقوى قبل النشر الواسع.
3. **اختبارات وسيط أوسع على Demo فقط:** حسابات Cent وStandard وECN، اختلاف الرموز والعقود، الرفض الفعلي بسبب السبريد واللوت والوقف، انتهاء الاشتراك، انقطاع الشبكة، إعادة تشغيل EA والخادم ومنع التكرار، رفض الوسيط والتعبئة الجزئية، وتسوية الصفقات المفتوحة مع سجل الوسيط بعد التعطل.
4. **الاستراتيجية:** استلم قواعد SES من المالك لاحقًا، ونفّذها في مكوّن خاص محدود الوصول يتصل بواجهة إشارات مُوثّقة ومراجَعة. لا تخترع استراتيجية أو تنشر منطقها السري في هذا المستودع.
5. **الاشتراكات والدفع:** `PaymentProvider` واجهة فقط. أضف وسيلة دفع بعد اختيارها وتحديد تكلفتها واختبارها، مع إدارة انتهاء الاشتراكات وتجديدها. لا تدّعِ أن الدفع الحالي يعمل.
6. **الإطلاق:** راجع شروط الوسيط وطريقة تشغيل EA، ودقّق إدارة المخاطر والخصوصية والمراقبة على بيئة ثابتة. التداول الحقيقي مغلق في الكود ويظل خارج نطاق النسخة الحالية.
