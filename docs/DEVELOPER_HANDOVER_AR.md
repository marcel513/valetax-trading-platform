## 2. نتيجة المراجعة الحالية

- قبل إضافة هذا التسليم، كان `HEAD` و`origin/main` ونتيجة `git ls-remote` متطابقة عند `eb389d694953da8582ce3af656233e5739e7ae28`، دون تغييرات محلية معلقة.
- أُعيد تشغيل `py -m pytest tests -q`: نجحت الاختبارات العشرة، مع 15 تحذير إهمال من الاعتماديات على Python 3.14. هذه اختبارات معزولة تستخدم قاعدة مؤقتة، وليست تنفيذ صفقات لدى الوسيط.
- تشغيل `py -m pytest -q` من المجلد المحلي القديم يجمع أيضًا نسخة التحقق داخل `work/verify-clone`، فيفشل بتعارض اسم وحدة الاختبار. استخدم `py -m pytest tests -q` لتحديد مجموعة الاختبارات الصحيحة.
- تحقق `getMe` من Telegram أعاد الاسم `ValetaxDemoPlatformBot` ومنع الانضمام إلى المجموعات. هذا يثبت صلاحية الرمز وهوية البوت وقت الفحص؛ لا يثبت تشغيل عامل استقبال الرسائل.
- ملف `.env` وقاعدة البيانات موجودان محليًا. لم يستجب `/health` المحلي على المنفذ 8000، ولم تظهر عمليتا Python المطابقتان لأوامر API والبوت وقت الفحص. لذلك لا تُعامل الخدمة القديمة باعتبارها تعمل حاليًا.
- لم تُفتح صفقات أو يُشغّل عامل Telegram جديد أثناء مراجعة التسليم، ولم تُعد تجربة MT5 في أكتوبر.

| `platform_app/bot.py` | استقبال Telegram بأسلوب long polling، معالجة الأوامر، إرسال التنبيهات المعلقة، استدعاء المراقبة |
| `platform_app/core.py` | تسجيل المستخدم، تجربة اشتراك 7 أيام، رموز الربط والدخول والجلسات، صلاحية الإدارة، ملكية الحساب وإعدادات المخاطرة |
| `platform_app/db.py` | SQLite، علاقات foreign keys، WAL، مهلة القفل، معاملات commit/rollback، إنشاء schema وسجل migration رقم 1 |

| `platform_app/strategy.py` | `Signal` و`StrategyProvider` و`ManualDemoProvider`؛ إشارات ذهب يدوية للاختبار فقط |

| `platform_app/monitor.py` | تنبيه انقطاع نبض EA لأكثر من دقيقتين، وملخص يوم سابق وفق UTC مع سجل يمنع تكرار إنشاء الحدث |
| `ea/ValetaxDemoEA.mq5` | EA إصدار 1.001؛ اتصال HTTPS؛ اكتشاف الذهب؛ فحوص الدخول؛ إرسال أوامر Demo؛ رصد إغلاق صفقات المنصة |
| `tests/test_platform.py` | 10 اختبارات لواجهات الخادم والمنطق والخصوصية ومنع بعض الانتقالات المكررة |

التقنية الحالية: Python وFastAPI وUvicorn وSQLite وhttpx وpython-dotenv وtruststore، واختبارات pytest. الواجهة HTML عربية بسيطة بداخل API؛ لا توجد واجهة React أو نظام نشر دائم مكتمل.

## 4. البيانات والتدفقات

الجداول: `schema_migrations`، `users`، `subscriptions`، `link_codes`، `accounts`، `risk_settings`، `signals`، `deliveries`، `orders`، `trades`، `events`، `alerts`، `web_codes`، `web_sessions`.

يُحفظ تجزؤ رمز EA ورموز الربط والدخول والجلسات في الخادم. رمز EA الخام يبقى في ملف محلي لدى MT5. القاعدة الفعلية تحتوي بيانات خاصة ولا تدخل المستودع العام.

تدفق الربط:

1. `/start` يسجل Telegram user ID ويربط محادثته الخاصة؛ التكرار لا ينشئ مستخدمًا آخر.
2. `/link` يصدر رمزًا عشوائيًا صالحًا 10 دقائق ولمرة واحدة.
3. المستخدم يسجل دخوله بنفسه في MT5 Demo، ثم يدخل الرمز وعنوان HTTPS في EA.
4. `POST /api/ea/link` يستهلك الرمز داخل معاملة، يرفض ربط حساب مكرر أو نوع غير Demo، وينشئ حسابًا ورمز EA وإعدادات متوقفة افتراضيًا.
5. EA يحفظ الرمز في `FILE_COMMON` باسم يتضمن رقم الحساب، ثم يُمسح رمز الربط من Inputs.
6. كل 15 ثانية تقريبًا يرسل EA النبض ومواصفات الذهب ويقرأ الإعدادات. يمكن أن يستمر الاتصال أثناء إيقاف الدخول.

تدفق الصفقة الحالي:

1. مسؤول يدخل BUY أو SELL وسعر وقف خسارة مطلق في `/admin`.
2. `ManualDemoProvider` ينشئ UUID وإشارة `DEMO_ONLY` للذهب تنتهي خلال دقيقتين.
3. الحساب المفعّل ذو الاشتراك الصالح يستطيع جلب الإشارة. الإشارات الحالية عامة للحسابات المؤهلة، وليست موجهة تلقائيًا لحساب اختبار واحد.
4. EA يتحقق من القيود، ويسجل معرف الإشارة محليًا قبل محاولة التنفيذ، ثم ينفذ أمر سوق عند النجاح.
5. تقرير التنفيذ يوثق order/deal/position/retcode والسعر والحجم؛ الخادم يسجل الصفقة ويضع تنبيه فتح في قائمة الإرسال.
6. عند اختفاء المركز ورصد صفقة الإغلاق من سجل الوسيط، يرسل EA تقرير الإغلاق والنتيجة شاملة الربح والعمولة والسواب، ويُرسل تنبيه الإغلاق.

## 5. البوت بالتفصيل

البوت الموجود هو `@ValetaxDemoPlatformBot`؛ إنشاء نسخة تطوير مستقلة أو إعادة استخدام نفس الرمز قرار تشغيلي. لا تشغّل عاملَي polling للرمز نفسه. حساب Gmail أو GitHub لا يمنح إدارة البوت في BotFather أو إدارة المنصة تلقائيًا.

| الأمر | السلوك الحالي |
|---|---|
| `/start`, `/register`, `/help` | تسجيل المستخدم عند الحاجة وعرض المساعدة وأوامر Demo |
| `/subscribe`, `/subscription` | عرض الحالة وتاريخ النهاية والتنبيه بأن الدفع غير مفعّل |
| `/link` | إصدار رمز الربط المؤقت لـMT5 |
| `/accounts` | عرض حسابات صاحب المحادثة فقط |
| `/ea` | عرض آخر نبض للحسابات المرتبطة |
| `/settings` | إرشاد المستخدم إلى `/dashboard` لتعديل المخاطرة |
| `/dashboard` | رابط دخول خاص صالح 5 دقائق ولمرة واحدة؛ ينشئ جلسة 12 ساعة |
| `/trades` | آخر عشر صفقات للحسابات التابعة للمستخدم |
| `/today` | عدد الصفقات المغلقة ومجموع الربح في اليوم حسب UTC |
| `/stop` | إيقاف فتح صفقات جديدة لكل حسابات المستخدم؛ لا يغلق المراكز المفتوحة |

الرسائل التي تحتوي نتائج الحساب لا تُعرض للمجموعات. الانضمام إلى المجموعات معطل في إعداد البوت وفق التحقق الحالي. محاولات الإرسال الفاشلة تظل في `alerts` ولا تغيّر حقيقة تنفيذ الصفقة؛ ما زال مطلوبًا اختبار الاستئناف ومنع التكرار عند أعطال التسليم بصورة أوسع.

سبق إصلاح مشكلة TLS على Windows باستخدام مخزن شهادات النظام عبر `truststore` دون إلغاء التحقق من الشهادات. وسبق إصلاح رابط الدخول من Telegram باستخدام `SameSite=Lax`؛ cookie من نوع HttpOnly، وSecure عند ضبط عنوان HTTPS. هذا لا يغني عن مراجعة أمان كاملة لنماذج الويب.

## 6. لوحة المستخدم والإدارة وواجهات API

لوحة المستخدم تعرض الاشتراك والحسابات وآخر اتصال ورمز الذهب وسجل الأحداث، وتعدل اللوت والأداة `XAU` وحد الصفقات وحد الخسارة اليومية وحد السبريد وتفعيل الدخول. المقصود إعداد لوت ثابت؛ لا يوجد احتساب تلقائي مكتمل للوت كنسبة مئوية من الرصيد. صلاحية الإدارة تعتمد `ADMIN_TELEGRAM_IDS` الرقمي في `.env`، وليست عنوان بريد إلكتروني.

لوحة الإدارة تعرض معلومات الحسابات والاشتراكات والأحداث، وتعدل حالة الاشتراك ونهايته، وتنشئ إشارات Demo يدوية. لا توجد بوابة دفع ولا خطط بيع مكتملة.

| المسار | الغرض والتوثيق |
|---|---|
| `GET /health` | فحص خدمة بسيط؛ يعرض تعطيل التداول الحقيقي؛ ليس فحصًا شاملًا للوسيط والبوت |
| `POST /api/ea/link` | رمز ربط لمرة واحدة؛ يعيد رمز EA |
| `POST /api/ea/heartbeat` | Bearer token للحساب؛ يتحقق من اتساق الهوية ويحدث مواصفات الرمز |
| `GET /api/ea/signals` | Bearer token؛ يعيد الإشارات الصالحة للحساب المسموح له |
| `GET /api/ea/open-trades` | Bearer token؛ الصفقات التي يسجلها الخادم كمفتوحة للحساب |
| `POST /api/ea/report` | Bearer token؛ تقارير rejected/submitted/filled/closed |
| `GET /login/{code}` | استهلاك رابط دخول خاص ثم تحويل إلى اللوحة |
| `GET /dashboard` | جلسة المستخدم |
| `POST /dashboard/settings/{account_id}` | تعديل حساب يملكه المستخدم |
| `GET /admin` | جلسة مسؤول |
| `POST /admin/subscription` | تعديل اشتراك بواسطة مسؤول |
| `POST /admin/demo-signal` و`POST /api/admin/demo-signal` | إنشاء إشارة يدويًا بواسطة مسؤول |

التقارير الموثقة برمز الحساب تُراجع حقولها وانتقالاتها، لكن الخادم لا يتحقق مستقلًا من صحة كل fill لدى الوسيط، ولا يثبت أن عميل HTTP آخر يقول الحقيقة بشأن Demo.

## 7. EA وحدود المخاطرة

Inputs: `ServerBaseUrl`، `OneTimeLinkCode`، `LocalPause` الافتراضي true، و`PlatformMagic` الافتراضي 90025001. يبدأ EA برفض الحساب الحقيقي والعنوان غير HTTPS، ويعيد فحص Demo في كل Timer. يتصل بـMT5 المكتبي على Windows أو VPS مناسب؛ الهاتف والويب لا يشغّلان هذا EA.

يفحص قبل الدخول: Demo، الإيقاف المحلي وإذن الخادم والاشتراك، اتصال الوسيط والسماح بالتداول، قابلية تداول الرمز وصلاحية السعر، السبريد، حجم اللوت وحدوده وخطوته، عدد مراكز المنصة، خسارتها اليومية، اتجاه وقف الخسارة ومسافته وشبكة tick size، والهامش و`OrderCheck`. يقرأ مواصفات العقد والرمز من منصة الوسيط؛ اكتشاف الرمز يبدأ بالرموز المحددة ثم قائمة الوسيط كاملة.

عدم الحصول على نبض ناجح يمنع الدخول الجديد. المراكز المفتوحة تحتفظ بوقفها عند الوسيط. لا يوجد بعد منطق استراتيجية لإدارة trailing/breakeven/TP متدرج. الإغلاق الذي اختُبر كان إجراء اختبار منفصلًا ثم رصد EA نتيجته، وليس تنفيذ قواعد خروج استراتيجية تلقائية.

منع التكرار محافظ: `VT_` مع UUID في Terminal Globals قبل محاولة التنفيذ، وقيود uniqueness في القاعدة. لا يوجد ضمان exactly-once موزع. المعرف المحلي غير مقيد بالحساب، ورمز الطلب الحالي هو signal UUID؛ يحتاج ذلك اختبارًا وإصلاحًا لتعدد الحسابات في نفس الطرفية وفي قاعدة الخادم. فشل إرسال تقرير بعد تنفيذ صفقة يمكن أن يترك فرقًا بين الوسيط والخادم؛ مطلوب outbox وتسوية من سجل الوسيط. لا تُعد إرسال إشارة قديمة عشوائيًا لحل الفرق.

## 8. ما اختُبر تاريخيًا في 25 سبتمبر 2026

- بناء EA 1.001 في MetaEditor الخاص بـValetax: صفر أخطاء وصفر تحذيرات.
- ربط حساب Valetax Demo فعلي عبر رمز البوت ونبض HTTPS من Cloudflare Quick Tunnel مؤقت.
- اكتشاف `XAUUSD.vx`؛ contract size 100 وtick size 0.01 وtick value 1، وحد/خطوة اللوت 0.01 وأقصاه 50 لذلك الحساب وقتها.
- اكتشاف خلل `OrderCheck`: قبول retcode صفر عند نجاح الفحص بالإضافة إلى `TRADE_RETCODE_DONE`؛ هذا مختلف عن تأكيد تنفيذ الأمر.
- فتح BUY واحد بحجم 0.01 لوت ووقف خسارة، ثم إغلاق مركز الاختبار وحده؛ أكد الوسيط الفتح والإغلاق بـretcode 10009.
- وصول إشعاري الفتح والإغلاق وظهور الصفقة في `/trades` و`/today`؛ النتيجة +0.44 بعملة Demo. هذه تجربة وظيفية واحدة ولا تثبت أداء استراتيجية.
- نهاية التجربة: لا مراكز مفتوحة وتعطيل الدخول من الخادم؛ المستخدم طلب وقتها إبقاء `LocalPause=false`. هذه حالة تاريخية يجب فحصها قبل أي تشغيل جديد.

الاختبارات العشرة تغطي: رمز الربط مرة واحدة ورفض live؛ الربط مع الإيقاف؛ انتهاء الرمز والحساب المكرر؛ عزل المستخدم والإدارة؛ الاشتراك والإيقاف الافتراضي؛ منع تكرار بعض تقارير التنفيذ؛ رفض تغير هوية النبض؛ خصوصية البوت وانتقال الإغلاق؛ تكرار start وملكية stop؛ وcookie رابط Telegram. لا تغطي كل منطق MQL5 ولا جميع أعطال الوسيط.

## 9. الاستراتيجية ELDOC10 والملفات الخاصة

ورد طلب لاحق باسم ELDOC10 لتحليل المؤشرات وقواعد الدخول والخروج وإدارة الصفقة، وإصدار نسخ v1/v2 مع تسجيل نسخة كل إشارة. محاولة العمل التالية في الشات توقفت قبل تنفيذها. الكود الموجود لا يتضمن ELDOC10؛ SES المذكور في التوثيق القديم ليس دليلًا على وجود استراتيجية أخرى مكتملة، ولا على أن الاسمين مترادفان.

المرجع المحلي 9 ملفات: 8 مؤشرات `.ex4` وقالب `DR Forex (4).tpl`. ملفات ex4 برامج MT4 مترجمة وليست مصدر mq4؛ لا يمكن استنتاج جميع قواعد التداول أو نقلها إلى MT5 بمجرد قراءتها. القالب مضبوط على BTCUSD فريم M1، بينما تجربة المنصة كانت على ذهب MT5؛ يجب حسم الأصل والفريم وقواعد التأكيد قبل الربط.

حسب طلب المالك الأصلي تبقى الملفات الأصلية ومنطق ELDOC10 خاصة، خارج المستودع العام. توجد قائمة الأسماء والبصمات في حزمة التسليم الخاصة عند مشاركتها. المطلوب استلام القواعد الصريحة أو مصدر المؤشرات/شرحها المصرّح به، تحديد التعارض والنقص، ثم تنفيذ مكوّن خاص مع واجهة إشارات موثقة. يلزم أيضًا ترحيل schema وتعديل API وEA اللذين يقبلان الآن `DEMO_ONLY` فقط؛ واجهة `StrategyProvider` ليست تكامل خدمة استراتيجية خارجية جاهزًا.

## 10. التشغيل من جهاز جديد

```powershell
git clone https://github.com/marcel513/valetax-trading-platform.git
cd valetax-trading-platform
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest tests -q
Copy-Item .env.example .env
```

أدخل القيم محليًا: `BASE_URL` عنوان HTTPS ثابت، `DATABASE_PATH` مسار قاعدة البيانات المقصودة، `TELEGRAM_BOT_TOKEN` رمز البوت، و`ADMIN_TELEGRAM_IDS` معرفات Telegram الرقمية للمسؤولين. ملف `.env.example` ليس بيانات دخول صالحة. تطوير الكود والاختبارات لا يحتاج تشغيل البوت أو حساب وسيط.

بعد تحديد ما إذا كانت نسخة مستقلة أو نقلًا لنفس الخدمة، وفي طرفيتين منفصلتين:

```powershell
.\.venv\Scripts\python.exe -m uvicorn platform_app.api:app --host 127.0.0.1 --port 8000
.\.venv\Scripts\python.exe -m platform_app.bot
```

أوقف الخدمات محليًا بـCtrl+C. انشر API خلف TLS صالح، ثم ابنِ EA في MetaEditor وأضف عنوان HTTPS في قائمة WebRequest واربط Demo بـ`/link`. ابدأ مع الإيقاف المحلي والخادمي. نسخ GitHub وحده لا ينقل مستخدمي البوت أو ارتباطات MT5 أو جلسات اللوحة. حافظ على نسخة احتياطية متسقة من SQLite قبل نقل الخدمة، وأوقف العامل القديم قبل تشغيل الجديد على الرمز نفسه. نقل الأسرار يكون بقناة خاصة مع المالك وبعد تحديد حدود إدارة البوت والاستضافة؛ لا تضعها في برومبت أو commit.

## 11. المتبقي مرتّبًا

1. **تثبيت التشغيل:** اختيار استضافة وHTTPS دائم؛ إعداد خدمات إعادة التشغيل والمراقبة؛ نقل قاعدة البيانات والأسرار بأمان؛ نسخ احتياطي SQLite واستعادة مجرّبة. توثيق النشر حاليًا إرشادات وليس إعداد خدمة مكتملًا.
2. **موثوقية التداول التجريبي:** تقارير قابلة لإعادة المحاولة وتسوية سجل الوسيط؛ اختبار الأعطال بعد التنفيذ وقبل التقرير؛ التعبئة الجزئية والرفض؛ ضبط request IDs ومنع التكرار لكل حساب؛ اختبار تعدد الحسابات والـEA؛ التحقق من parsing JSON الحالي الهش ومن مطابقة الذهب عند وجود أكثر من رمز.
3. **الأمان:** مراجعة CSRF والجلسات وrate limiting ورموز الربط؛ الإلغاء والتدوير؛ تحقق أقوى من الحساب والتنفيذ؛ اختبارات عزل وصلاحيات أوسع؛ منع كشف الرموز في السجلات. `schema_migrations` الحالي أساس بسيط وليس نظام ترحيلات تاريخية مكتملًا للتغييرات المقبلة.
4. **توسيع Demo:** Cent/Standard/ECN واختلاف العقود والرموز والهامش والسبريد والوقف؛ انتهاء الاشتراك والانقطاع؛ إعادة التشغيل ومنع إعادة التنفيذ؛ اتساق اليوم UTC مع يوم الوسيط المستخدم لحساب حد الخسارة. راجع أن إعادة HistorySelect قد تتداخل بين وظائف EA.
5. **ELDOC10:** جمع القواعد وتحديد الأصل والفريم؛ مكوّن خاص وإصدارات مع سجل لكل إشارة؛ اختبارات أمثلة واضحة وbacktest/forward test على Demo. لا توجد نتائج استراتيجية مثبتة حاليًا.
6. **الاشتراكات والدفع:** اختيار مزود ثم checkout والتحقق من إشعارات الدفع وتجديد/انتهاء الاشتراك. الاشتراك التجريبي الحالي 7 أيام ويجوز تعديله إداريًا؛ لا توجد تحصيلات آلية. راجع قواعد المزود وTelegram عند تنفيذ الدفع لاحقًا.
7. **تجهيز الاستخدام الأوسع:** تشغيل ومراقبة قابلان للصيانة، مراجعة الخصوصية وشروط الوسيط وتجربة استعادة وتعطل كاملة. الحسابات الحقيقية تظل مرفوضة في هذه النسخة.

## 12. حدود الإتاحة وتسليم التشغيل

الكود العام متاح للقراءة والنسخ لأي حساب. رفع تعديلاته إلى المستودع نفسه يحتاج دعوة GitHub مقبولة. البريد وحده لا يثبت اسم حساب GitHub. الوصول إلى المستودع لا يمنح تلقائيًا صلاحية BotFather أو الخادم أو MT5 أو الأسرار.

خارج Git عمدًا: `.env`، قاعدة البيانات وWAL/SHM، رموز EA في MT5 Common Files، رموز الربط والجلسات، السجلات، ملفات `.ex5`، مخرجات الاختبار، وملفات ELDOC10 الأصلية. لا تشارك نسخة كاملة عمياء من مجلد المشروع لأنها تحتوي هذه البيانات.

كان داخل `work/` مساعد فحص تاريخ Git، وأداة إغلاق صفقة الاختبار لمرة واحدة، وسجل تجميع ونسخة clone للتحقق. هذه أدوات تجربة وليست خدمات إنتاج. يمكن تسليم مصدري المساعدين في الحزمة الخاصة بعد المراجعة؛ أداة الإغلاق غير مطلوبة للتشغيل المعتاد ولا تُشغّل تلقائيًا. MetaTrader5 Python الذي تستخدمه أداة التجربة ليس اعتمادًا لازمًا لتشغيل API والبوت.

المطور يستلم الكود والتوثيق والاختبارات، ثم يحدد مع المالك ما يحتاجه من إدارة تشغيل. المطلوب تقرير صريح بما تحقق الآن وما هو مثبت تاريخيًا فقط، وتحديث التوثيق مع كل تغيير.
