1) افهم الفكرة والبنية الموجودة
المنتج منصة لوسيط Valetax وMT5 والذهب، متعددة المستخدمين، نسختها الحالية Demo فقط. المستخدم يفتح حسابه ويسجل دخوله ويودع لدى الوسيط بنفسه. منصتنا لا تستلم ودائع ولا كلمات مرور حسابات التداول. الخادم يدير المستخدمين والاشتراكات والإشارات والسجلات؛ EA داخل MT5 المكتبي هو الذي يفحص المخاطرة ويرسل أوامر الوسيط. الاستراتيجية النهائية والدفع والاستضافة الدائمة لم تكتمل.

الكود: FastAPI وUvicorn وSQLite وTelegram long polling، ولوحتان HTML بالعربي، وEA بلغة MQL5 إصدار 1.001. api.py للـAPI واللوحات؛ bot.py للبوت؛ core.py للمستخدم والربط والصلاحيات؛ db.py للجداول؛ security.py للرموز والتوقيت؛ monitor.py للتنبيه والملخص اليومي؛ strategy.py لواجهة الاستراتيجية والمزود اليدوي؛ payment.py واجهة دفع غير مفعلة. لا تستبدل ده بواجهة شكلية أو بيانات ثابتة.

2) البوت والربط والاشتراك
البوت @ValetaxDemoPlatformBot اتعمل بالفعل من BotFather، واتضبط وصفه وأوامره ومنع الانضمام إلى المجموعات. آخر فحص في 26 أكتوبر 2026 أكد هوية البوت وصلاحية الرمز محليًا؛ API المحلي وعامل البوت لم يكونا شغالين وقت الفحص، فلا تفترض إنه بيرد الآن.

الأوامر:
/start /register /help: تسجيل وعرض مساعدة.
/subscribe /subscription: حالة الاشتراك، بدون دفع فعلي.
/link: رمز ربط 10 دقائق لمرة واحدة، يُدخل في EA داخل MT5 Demo.
/accounts: حسابات صاحب المحادثة.
/ea: آخر نبض.
/settings: توجيه للوحة لضبط المخاطرة.
/dashboard: رابط دخول خاص 5 دقائق لمرة واحدة وجلسة 12 ساعة.
/trades: آخر 10 صفقات.
/today: نتيجة الصفقات المغلقة حسب يوم UTC.
/stop: إيقاف الدخول الجديد لكل حسابات المستخدم، وليس إغلاق المراكز.

التسجيل متكرر بأمان ويبدأ بتجربة اشتراك 7 أيام. حالات الاشتراك trial/active/expired/suspended. الإدارة حاليًا عبر ADMIN_TELEGRAM_IDS الرقمية في .env، مش Gmail. فشل إرسال تنبيه يتركه معلقًا دون تغيير سجل الصفقة. مراقبة الانقطاع والملخص اليومي تعمل داخل دورة البوت، وليست خدمة منفصلة. لا تشغل عاملَي polling لنفس Bot Token.

3) الـAPI والـEA
المسارات الأساسية /health و/api/ea/link و/api/ea/heartbeat و/api/ea/signals و/api/ea/open-trades و/api/ea/report، ولوحتا /dashboard و/admin. الربط مؤقت لمرة واحدة، وبعده Bearer token للحساب. الخادم يخزن hashes للرموز. EA يحفظ رمزه محليًا في MT5 Common Files. لا تنشر الرمز أو تعيد استعمال رمز ربط قديم.

EA يرفض الحساب الحقيقي في OnInit وOnTimer، ويتطلب HTTPS صحيحًا وWebRequest مسموحًا به. Inputs هي ServerBaseUrl وOneTimeLinkCode وLocalPause وPlatformMagic. يرسل نبضًا كل 15 ثانية تقريبًا، ويكتشف الذهب من قائمة الوسيط ومواصفات العقد واللوت؛ الرمز الذي اختُبر سابقًا XAUUSD.vx. يفحص الاشتراك والإيقاف والاتصال والسبريد واللوت وعدد المراكز وحد الخسارة اليومي والهامش والوقف والـOrderCheck قبل أمر السوق. لا تفترض أن Cent وStandard وECN نفس مواصفات العقد.

المزود الحالي ManualDemoProvider ينشئ إشارات XAU يدوية BUY/SELL بوقف خسارة ومعرف UUID وصلاحية دقيقتين، ووسم DEMO_ONLY. ليست استراتيجية تلقائية. الإشارات الحالية متاحة لكل الحسابات المؤهلة المفعلة؛ لا تنشئ إشارة اختبار قبل التأكد من نطاق كل الحسابات المتصلة. الكود وقاعدة البيانات وEA يقيّدون provider بهذا الوسم، لذلك تركيب مزود خاص يتطلب تكاملًا وترحيل schema واختبارات فعلية.

4) ما اتعمل واتختبر فعلًا
في 25 سبتمبر 2026 جُمّع EA 1.001 بصفر أخطاء وصفر تحذيرات، واتربط Valetax Demo فعليًا عبر HTTPS باستخدام Cloudflare Quick Tunnel مؤقت. اتصلت مواصفات الذهب للخادم والبوت واللوحة.

تم إصلاح فحص OrderCheck لقبول retcode صفر عند نجاح precheck، وإصلاح تشخيص أخطاء WebRequest، واستخدام مخزن شهادات Windows للاتصال، وإصلاح cookie الدخول من Telegram إلى SameSite=Lax.

اتفتحت صفقة BUY واحدة 0.01 لوت بوقف خسارة على XAUUSD.vx ثم اتقفلت صفقة الاختبار وحدها. الوسيط أكد الفتح والإغلاق بـ10009. البوت عرض رسائل الفتح والإغلاق و/trades و/today. النتيجة +0.44 بعملة Demo هي نتيجة اختبار وظيفة واحدة، مش قياس أرباح استراتيجية. نهاية الاختبار وقتها ماكانش فيه مراكز مفتوحة، واتقفل الدخول من الخادم؛ المستخدم اختار إبقاء LocalPause=false. افحص الحالة مجددًا؛ ده وصف تاريخي مش حالة تشغيل مضمونة الآن.

في 26 أكتوبر 2026 كان الكود المحلي مطابقًا لـorigin/main عند eb389d6 قبل إضافة مستندات التسليم الجديدة، ونجحت الاختبارات العشرة بأمر py -m pytest tests -q مع تحذيرات إهمال اعتماديات. لا تخلط اختبارات Python المعزولة مع اختبار تنفيذ وسيط. لم نعد تجربة MT5 في أكتوبر.

5) ابدأ على جهازك
افحص git status وتعليمات AGENTS.md إن وجدت، واحفظ أي تعديلات حالية قبل pull. لو نسخة جديدة اعمل clone؛ لو موجودة وحديثة استخدم git pull --ff-only دون مسح شغل محلي. أنشئ بيئة Python مستقلة وثبت requirements.txt، وشغل python -m pytest tests -q. المجلد القديم يحتوي work/verify-clone؛ تشغيل pytest من الجذر بدون تحديد tests يجمع النسختين ويتعارض.

لتشغيل نسخة مستقلة: انسخ .env.example إلى .env وأدخل الإعدادات محليًا. للتطوير والاختبارات وحدها لا تحتاج رمز البوت أو MT5. لتشغيل نفس الخدمة الحية، اتفق مع المالك على نقل قاعدة البيانات والأسرار وإيقاف العامل القديم أولًا. لا تطلب كتابة الرموز في الشات ولا تستخدم .env.example كأنه بيانات حقيقية.

أوامر التشغيل من البيئة الصحيحة في طرفيتين:
python -m uvicorn platform_app.api:app --host 127.0.0.1 --port 8000
python -m platform_app.bot
ابدأ والـEA والخادم متوقفان عن الدخول. الخادم يحتاج HTTPS دائمًا للـEA، وMT5 Desktop لازم يظل مفتوحًا ومتصلًا. GitHub لا يشغل الخادم ولا ينقل قاعدة البيانات أو ملكية البوت تلقائيًا.

6) الاستراتيجية المطلوبة ELDOC10
ورد طلب لاحق لتحليل 8 ملفات مؤشرات ex4 وقالب MT4 باسم DR Forex (4).tpl لاستراتيجية ELDOC10، لكن التنفيذ توقف قبل إنجازها. الاستراتيجية غير موجودة في الكود الحالي. SES اسم قديم في التوثيق؛ لا تفترض أنه نفس ELDOC10.

الملفات الأصلية خاصة ولا تُنشر في GitHub العام. استلمها من حزمة التسليم الخاصة التي يشاركها المالك. ex4 برامج MT4 مترجمة وليست mq4؛ لا تفك حمايتها ولا تختلق قواعد غير مثبتة. القالب على BTCUSD/M1 بينما المنصة اختُبرت على ذهب MT5؛ حدّد الأصل والفريم مع المالك. اجمع قواعد الدخول والخروج وإدارة الصفقة والوقف وتوقيت الإشارات، واكشف النواقص والتعارضات. بعدها اعمل مكون استراتيجية خاص وإصدارات ELDOC10 v1/v2، وسجل نسخة كل إشارة، واختبارات بأمثلة وقواعد معروفة ثم Demo. لا تدّعِ أن الملفات وحدها تكفي لإعادة بناء كل منطق المؤشرات.

7) كمل حسب الأولوية
أولًا تشغيل دائم: تجهيز نشر HTTPS وخدمات restart ومراقبة ونسخ احتياطي SQLite واستعادة فعلية. نفذ ما يمكن محليًا دون شراء خدمة، واجعل أي تكلفة تحتاج موافقة محددة.
ثانيًا موثوقية Demo: outbox وإعادة محاولة التقارير وتسوية تاريخ الوسيط؛ حالات التعطل بعد التنفيذ قبل التقرير؛ رفض الوسيط والتعبئة الجزئية؛ معرف طلب ومنع تكرار لكل حساب؛ دعم تعدد الحسابات واختبارات EA الفعلية؛ متانة JSON واختيار الرمز.
ثالثًا الأمان: مراجعة CSRF والجلسات وrate limits وإلغاء وتدوير الرموز وعزل المستخدمين والتحقق الأقوى من نوع الحساب والتنفيذ. الخادم يثق حاليًا بتقرير EA الموثق ولا يثبت fill مستقلًا.
رابعًا اختبارات Cent/Standard/ECN والسبريد والوقف والهامش وانتهاء الاشتراك والانقطاع وإعادة التشغيل وفروق يوم الوسيط وUTC. حد اللوت الحالي ثابت؛ إدارة مخاطرة بنسبة من الرصيد ليست ميزة مكتملة.
خامسًا قواعد ELDOC10 وتكاملها الخاص مع schema/API/EA وإصداراتها واختبارها.
سادسًا مزود الدفع بعد اختياره والتحقق من قواعده وربط checkout والتحقق من الإشعارات وتجديد الاشتراك. PaymentProvider حاليًا واجهة فقط.

خلي التداول الحقيقي مرفوضًا في هذه النسخة، وكل اختبار أوامر على Demo فقط وبحدود واضحة ووقف خسارة. لا تنفذ أوامر من أدوات التجربة القديمة تلقائيًا. لا تعرض أي نسبة نجاح بدون تقييم فعلي.
